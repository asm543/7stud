# 포커 토너먼트 온라인 (노리밋 홀덤 · 7카드 스터드)

친구와 방을 만들어 토너먼트를 하는 웹 앱이에요. 방마다 게임을 고를 수 있어요.

- **노리밋 텍사스 홀덤**: WSOP 메인 이벤트 방식(빅블라인드 앤티) + TDA 룰. 2~9명.
- **7카드 스터드**: 고정 리밋 대회 룰. 2~7명.

계정 없이 방 코드나 초대 링크만 있으면 들어올 수 있고, 빈자리는 컴퓨터 상대가 채워요.

- 서버가 딜러: 셔플, 컴퓨터 판단, 룰 판정을 모두 서버에서 해요. 각 브라우저는 **자기 카드만** 받아서, 개발자 도구로 봐도 남의 카드는 없어요 (쇼다운·올인 공개분 제외).
- 게임 선택: 홈 화면에서 새 방의 게임을 고르고(브라우저에 기억), 로비에서 방장이 바꿀 수도 있어요. 최대 인원(9 ↔ 7)에 맞춰 넘치는 사람은 관전자로 돌아가요.
- 개인별 모드: 연습(힌트, 스터드는 죽은 카드도 표시) / 실전(힌트 없음, 스터드는 폴드한 카드를 서버가 아예 안 보냄).
- 턴 제한 시간(20/30/60초/없음), 끊겨도 같은 브라우저로 다시 들어오면 같은 자리로 복귀, 대회 중 들어온 사람은 관전, 끝나면 같은 방에서 한 판 더.
- 채팅: 로비·게임·관전 모두 사용 가능. 빠른 문구(nh, gg, ㅋㅋㅋ…), 시스템 안내(입장, 게임 변경, 대회 시작, 레벨업, 사람의 팟 획득·탈락, 우승), 재접속하면 최근 80개 복원.
- 화면: 데스크톱은 테이블 오른쪽에 채팅, 핸드 기록은 그 아래 접힌 아코디언. 1100px 미만에서는 액션 바의 채팅 버튼으로 아래 시트를 열어요. 760px 미만에서는 좌석이 두 줄로 쌓이고, 내 차례가 오면 내 카드가 액션 바에 가리지 않게 스크롤돼요.

## 노리밋 홀덤 룰

| 항목 | 내용 |
|---|---|
| 시작 스택 | 20,000 (레벨 1 기준 100BB) |
| 레벨 | 100/200 → 200/300 → 200/400 → 300/600 → … → 20,000/40,000 (20레벨), 앤티는 늘 빅블라인드와 같음 |
| 레벨업 간격 | 10핸드(표준) · 7핸드(터보) · 5핸드(하이퍼). 컴퓨터 9명 기준 표준은 평균 95핸드쯤에 끝나요 |
| 빅블라인드 앤티 | 빅블라인드가 테이블 전체 앤티를 냄. 칩이 모자라면 **블라인드를 먼저** 채우고 남는 칩으로 앤티(TDA 2024 RP-11). 앤티는 줄이지 않음. 앤티는 데드 머니라 메인 팟에 들어감 |
| 버튼 | 매 핸드 왼쪽으로. 탈락자가 생기면 **데드 버튼**: 빅블라인드는 항상 한 칸씩, 직전 빅블라인드 자리가 스몰(탈락했으면 데드 스몰), 직전 스몰 자리가 버튼 |
| 헤즈업 | 버튼이 스몰블라인드, 프리플랍은 버튼이 먼저·플랍부터는 빅블라인드가 먼저. 헤즈업으로 바뀔 때 같은 사람이 빅블라인드를 두 번 연속 내지 않게 맞춤 |
| 베팅 | 최소 베트 = 빅블라인드. 레이즈는 직전 풀 베트·레이즈 크기 이상. 빅블라인드가 짧아도 콜 금액은 레벨의 빅블라인드 |
| 숏 올인 | 풀 레이즈보다 적은 올인은 이미 액션한 사람에게 레이즈를 다시 열지 않음(콜·폴드만). 여러 숏 올인이 합쳐 풀 레이즈 이상이면 다시 열리지만, 최소 레이즈 크기는 마지막 풀 레이즈 그대로 |
| 정산 | 콜 받지 못한 베트는 반환. 사이드팟. 올인으로 더 베팅이 없으면 남은 사람 카드를 공개하고 보드를 끝까지 깜. 분할 팟의 남는 칩은 버튼 왼쪽에 가까운 승자에게. 폴드한 카드는 공개 안 함 |

베트 크기는 크기 버튼(프리플랍 오픈은 최소·2.5BB·3BB·팟·올인, 그 밖에는 최소·½팟·¾팟·팟·올인), 슬라이더(작은 금액을 세밀하게 고르도록 곡선), 직접 입력 중 편한 걸 쓰면 돼요. 서버는 보낸 금액을 항상 최소~올인 범위로 맞춰요.

연습 모드 힌트(H): 핸드 종류와 상위 몇 %, 지금 패, 무작위 상대 대비 승률과 팟 오즈로 계산한 필요 승률, 드로우, 다음 카드에 족보가 오르는 장수.

## 컴퓨터 상대

컴퓨터는 대회마다 이름(12개 중)과 스타일(10개 중)을 겹치지 않게 무작위로 받아요. 스타일은 화면에 표시하지 않아요. 두 게임 모두 같은 10가지 스타일을 쓰고, 홀덤에서는 스타일마다 오픈 범위·림프 성향·콜 범위·3벳 빈도·컨티뉴에이션 베트·베트 크기가 더 붙어요 (`public/holdem.js`의 `NL_TRAITS`). "앤티 도둑"은 홀덤에서 "블라인드 도둑"이 돼요.

| 스타일 | 특징 |
|---|---|
| 바위 | 좋은 패만 들어오고 블러프가 거의 없음. 레이즈를 받으면 잘 접음 |
| 겁쟁이 타이트 | 들어오긴 하지만 레이즈 한 번이면 대부분 접음 |
| 정석 (TAG) | 참가는 적고, 들어오면 공격적 |
| 균형형 | 약간 타이트·공격적이며 스틸·블러프·슬로플레이를 섞음 |
| 공격형 (LAG) | 많이 들어오고 많이 올림. 드로우로도 세게 침 |
| 매니악 | 거의 모든 판에 들어와 레이즈를 퍼부음 |
| 콜링 스테이션 | 웬만하면 콜, 잘 안 접음, 레이즈는 드묾 |
| 드로우 추격자 | 느슨하게 들어와 플러시·스트레이트 드로우를 끝까지 쫓음 |
| 함정파 | 아주 강한 패는 3~5구에서 숨겼다가 6·7구에 레이즈 |
| 앤티 도둑 | 3구 스틸은 자주, 저항을 받으면 쉽게 물러남 |

스타일은 출발점일 뿐이고, 각 컴퓨터는 "실제 사람이라면"을 전제로 대회 중에 흔들려요. 기준 실력은 지역 대회 Day1 우승 경험자 정도예요.

- 손읽기: 상대가 이번 핸드에 베트·레이즈했으면 그 행동에 어울리는 패일수록 무게를 둬서 승률을 계산해요. 평소 레이즈를 남발하거나 블러프가 들킨 적 있는 상대는 약한 패도 넓게 봐요.
- 상대 적응: 모두가 볼 수 있는 행동 통계(참가율, 공격 비율, 스틸 시도·성공, 스틸에 접는 비율, 베팅에 접는 비율, 들킨 블러프)를 쌓아서, 잘 접는 사람에게 스틸·블러프를 늘리고, 콜 잘하는 사람에게는 블러프를 줄이고 얇게 밸류 베팅해요. 스틸을 자주 하는 사람에게는 넓게 방어하고, 레이즈를 남발하는 사람에게는 맞받아쳐요. 사람 플레이어의 습관도 똑같이 기록돼요.
- 팟 오즈: 5·6구 콜은 앞으로 낼 빅 베팅까지 계산해요. 팟에 많이 넣었으면 쉽게 안 접어요.
- 틸트: 큰 팟을 잃거나 역전패하면 몇 핸드 동안 느슨하고 공격적으로 변하고 죽은 카드를 덜 기억해요. 회복 속도는 스타일마다 달라요.
- 테이블 이미지: 블러프가 쇼다운에서 들키면 한동안 블러프를 줄이고, 센 패를 보여준 뒤에는 블러프를 늘려요.
- 기어 변속: 정석·균형형·공격형 등은 8~14핸드마다 타이트·루즈를 바꿔요.
- 스택과 대회 단계: 스택이 한 바퀴 비용(앤티 전원 + 브링인)의 4배 미만이면 한 판에 걸고, 큰 스택은 작은 스택을 압박해요. 버블에서는 중간 스택이 몸을 사리고 칩 리더가 스틸을 늘려요. 헤즈업에서는 모두 느슨해져요.
- 기억 실수: 스타일마다 죽은 카드를 기억하는 정도가 달라요 (88~99%, 틸트 중에는 더 떨어짐).
- 채팅: 역전패, 큰 팟, 블러프 들킴, 탈락 때 가끔 한마디 해요 (핸드당 최대 1명).

### 홀덤 컴퓨터가 생각하는 방식

- 프리플랍: 169개 핸드 순위표(`scripts/gen-preflop.js`로 몬테카를로 생성, 1명·3명 상대 승률을 섞어서 수딧 커넥터·포켓 페어도 제자리)에서 내 핸드가 상위 몇 %인지 보고, 뒤에 남은 인원(포지션)별 오픈 범위 × 스타일로 오픈. 스틸 자리에서는 블라인드가 스틸에 잘 접을수록 넓혀요.
- 스택이 10~14BB 아래로 짧아지면 포지션별 푸시/폴드로 바꿔요.
- 레이즈를 마주하면 상대의 공개 통계(참가율·레이즈 비율·3벳 비율)와 포지션으로 짐작한 레인지에서 상대 패를 뽑아 승률을 계산하고, 리레이즈(밸류, 가끔 에이스·수딧 블러프) / 콜(팟 오즈 + 포지션·임플라이드 오즈·뒤에 남은 사람) / 폴드를 정해요. 레이즈를 남발하는 상대는 레인지를 넓게 봐요.
- 플랍 이후: 상대 패를 프리플랍 레인지에서 뽑되, 베트·레이즈한 상대는 그 행동과 어울리는 패(탑 페어 이상·드로우)일수록, 콜만 한 상대는 뭔가 걸린 패일수록 가중치를 줘서 승률을 계산해요. 그걸로 밸류 베트·레이즈, 컨티뉴에이션 베트(마른 보드일수록 자주), 턴 배럴, 드로우 세미블러프, 체크로 넘어오면 포지션에서 찔러보기, 팟 오즈 콜(드로우는 임플라이드 오즈)을 정하고, 팟에 많이 넣었으면 쉽게 안 접어요.
- 사람 같은 흔들림(틸트·이미지·기어·스택·버블·헤즈업·집중력)은 스터드와 같은 방식이에요. 홀덤에서 역전패는 올인 시점 승률 60% 이상이었다가 진 경우로 판단하고, 집중력이 떨어지면 판단에 잡음이 섞여요.
- 베트 금액은 사람처럼 스몰블라인드 단위로 반올림해요.

`node test/holdem.test.js 300 both`로 확인한 개발 시점 결과:

| 비교 | 결과 |
|---|---|
| 컴퓨터 9명, 스타일별 우승률 (공정 11.1%) | 공격형 18.8 · 매니악 17.4 (입상률은 26.6%로 낮음) · 균형형 13.7 · 블라인드 도둑 12.5 · 정석 11.9 · 함정파 11.2 · 드로우 추격자 7.3 · 겁쟁이 타이트 7.2 · 바위 7.1 · 콜링 스테이션 4.5 |
| 매 핸드 올인 봇 1명 + 컴퓨터 8명 | 봇 우승 4.0% (공정 11.1%) |
| 무조건 콜 봇 / 항상 최소 레이즈 봇 | 150판 중 우승 0번 |
| 단순 타이트 "ABC" 봇 4명 + 컴퓨터 5명 | 컴퓨터 우승 점유율 98.8% (공정 55.6%) |

스타일별 VPIP/PFR은 바위 20/10, 정석 27/17, 공격형 37/26, 매니악 50/37, 콜링 스테이션 36/6 정도예요 (대회 후반 푸시/폴드 구간 포함). 판단 한 번에 0.2ms 정도 걸려요.

### 스터드 비교 테스트

`node test/engine.test.js 200 both`를 돌리면 이전 버전 컴퓨터 3명과 새 컴퓨터 4명을 섞은 테이블 비교도 나와요. 개발 시점 결과는 새 컴퓨터 우승 점유율 84% (공정 기준 57%)였어요.

값은 `public/engine.js`의 `STYLES`에 있어요 (enter, raise, aggr, bluff, steal, sticky, respect, slowplay, semibluff, chase, focus, tiltProne, recover, shift, adapt, icm, talk). `node test/engine.test.js 200`을 돌리면 스타일별 우승률·입상률·참가율·공격 비율이 나와요.

## 로컬에서 실행

Node.js 18 이상이 필요해요.

```bash
npm install
npm start
```

브라우저에서 http://localhost:3000 을 열면 돼요. 같은 와이파이의 친구는 `http://<내 PC IP>:3000` 으로 들어올 수 있어요.
포트는 환경 변수 `PORT`로 바꿀 수 있어요.

테스트:

```bash
npm test
```

- `test/engine.test.js`: 스터드 족보 평가 단위 테스트 + 컴퓨터끼리 대회 (칩 보존, 레이즈 캡, 베팅 매칭, 스타일별 통계)
- `test/holdem.test.js`: 홀덤 룰 단위 테스트 31개(BBA 빅블라인드 우선, 최소 레이즈, 숏 올인 재오픈 금지·누적 재오픈, 헤즈업 순서, 데드 버튼, 앤티는 메인 팟, 콜 받지 못한 베트 반환, 짧은 빅블라인드, 남는 칩 순서, 사이드팟) + 컴퓨터끼리 대회(모든 액션이 범위 안인지, 매 액션 칩 보존) + 기준·공략 봇 비교. `node test/holdem.test.js [대회 수] [all|mixed|exploit|both]`
- `test/online.test.js`: 서버를 띄우고 봇으로 스터드 대회 완주, 히든 카드 유출 검사, 재접속, 관전, 리매치, 헤즈업, 채팅, 그리고 로비 게임 전환(9 ↔ 7 관전자 조정)과 홀덤 9명 대회 완주(범위 밖 레이즈 금액 보정, 홀카드 유출 검사)

2. Render 대시보드에서 **New → Blueprint** → GitHub 저장소 연결 → 저장소 선택. `render.yaml`을 읽어서 무료 웹 서비스를 만들어요.
   - Blueprint 대신 **New → Web Service**로 해도 돼요: Runtime `Node`, Build Command `npm install`, Start Command `npm start`, Instance Type `Free`, Health Check Path `/healthz`.
3. 배포가 끝나면 `https://<서비스 이름>.onrender.com` 으로 접속해서 방을 만들고, 초대 링크를 친구에게 보내면 끝이에요.

이후 `main` 브랜치에 push하면 자동으로 다시 배포돼요.

### 무료 플랜에서 알아둘 점

- 15분 동안 아무 요청도 없으면 서버가 잠들고, 다음 접속 때 깨어나는 데 1분 정도 걸려요. 페이지를 열어 둔 동안에는 클라이언트가 25초마다 신호를 보내서 잠들지 않아요.
- 방과 대회 상태는 메모리에만 있어요. 재배포하거나 서버가 재시작되면 진행 중인 방은 사라져요.
- 서버 인스턴스 하나를 전제로 만들었어요 (여러 대로 늘리면 방이 서로 안 보여요).

## 구조

```
server.js              HTTP(정적 파일, /healthz) + WebSocket(/ws) 방 서버 (GAMES에 게임별 엔진·최대 인원·레벨업 간격)
public/engine.js       7스터드 엔진 (서버·브라우저 공용): 족보 평가, 승률 추정, 토너먼트, 컴퓨터 판단. 홀덤도 족보 평가를 여기서 씀
public/holdem.js       노리밋 홀덤 엔진 (서버·브라우저 공용): 레벨, 데드 버튼, NL 베팅, 사이드팟, 프리플랍 순위표, 컴퓨터 판단, 힌트
public/index.html      화면: 홈(게임 선택·방 만들기/참가), 로비, 테이블(게임별), 결과
scripts/gen-preflop.js 프리플랍 169개 핸드 순위표 생성기
test/                  엔진·온라인 테스트
render.yaml            Render Blueprint
```

### 메시지 (JSON, `/ws`)

브라우저 → 서버

| t | 내용 |
|---|---|
| `create` | `{token, name, game?}` 새 방 (`game`: `'holdem'`(기본) \| `'stud'`) |
| `join` | `{code, token, name}` 참가 또는 재접속 (같은 token이면 같은 자리) |
| `mode` | `{mode: 'practice' \| 'real'}` 내 모드 |
| `settings` | `{patch: {game, ais, hpl, speed, turnSecs}}` 방장만, 로비에서 (`hpl`은 홀덤 10/7/5, 스터드 6/4/3) |
| `start` / `rematch` | 방장만 |
| `act` | `{handNo, i, type, to?}` 내 차례 액션 (legal 배열 인덱스). 홀덤 베트·레이즈는 `to`(총 베팅 금액)를 보내면 서버가 min~max로 맞춤 |
| `ready` | 다음 핸드 준비 |
| `chat` | `{text}` 채팅 (최대 200자, 0.6초 간격 제한) |
| `leave` / `ping` | 나가기 / 연결 유지 |

서버 → 브라우저: `joined {code, clientId}`, `state {room, you, game, turn?, yourTurn?, next?}`, `chat {reset?, items}`, `error {code, msg}`, `left`.

`game.type`이 `'holdem'`이면 플레이어마다 `hole`(남의 카드는 공개 전까지 `null`, 폴드한 남의 카드는 빈 배열), `hand`에 `board, buttonSeat, sbSeat, bbSeat, currentBet, minRaise, runout`, 그리고 `level, nextLevel`이 와요. 홀덤의 베트·레이즈 legal 항목에는 `min, max`(올인)가 있어요.

채팅 항목: `{id, ts, kind: 'user' | 'system', from: clientId | null, name, text}`. 참가 직후에는 `reset: true`로 최근 기록 전체가 와요.

### 조정할 만한 값 (`server.js` 위쪽 상수)

- `GAMES` 게임별 최대 인원(홀덤 9, 스터드 7), 레벨업 간격 선택지, 컴퓨터 승률 시뮬레이션 횟수
- `MAX_ROOMS` 200, `MAX_MEMBERS` 16 (관전 포함)
- `ROOM_IDLE_MS` 아무도 없는 방을 지우는 시간 (30분)
- `SPEED_MS` 컴퓨터 진행 속도, `DISCONNECTED_TURN_SECS` 연결이 끊긴 사람의 자동 액션 대기 (45초)
- `CHAT_KEEP` 방마다 보관하는 채팅 수 (80), `CHAT_MAX_LEN` 한 번에 보낼 수 있는 글자 수 (200), `CHAT_MIN_INTERVAL_MS` 연속 전송 간격 (0.6초)

단축키: F 폴드 · C 체크/콜/브링인 · R 컴플리트/베트/레이즈(홀덤은 고른 금액으로) · H 힌트 · Enter 다음 핸드(금액 입력칸에서는 그 금액으로 레이즈) · / 채팅 입력 · Esc 닫기

## 알려진 한계

- 계정·전적 저장이 없어요. 칩은 가상이고 실제 돈과 관계없어요.
- 방 코드를 아는 사람은 누구나 들어올 수 있어요 (자리가 없거나 대회 중이면 관전).
- 힌트의 승률은 상대 패를 무작위로 가정한 추정이라, 레이즈한 상대에게는 실제보다 낙관적이에요 (컴퓨터는 상대 행동으로 레인지를 좁혀서 계산해요).
- 홀덤은 한 테이블(최대 9명) 싱글 테이블 토너먼트예요. 여러 테이블 밸런싱, 레이트 등록, 리엔트리는 없어요.
- 기존 서비스 이름(`render.yaml`의 `stud7-online`)과 브라우저 저장 키는 이미 배포한 주소·재접속이 깨지지 않게 그대로 뒀어요.
